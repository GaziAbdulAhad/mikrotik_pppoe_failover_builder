ROUTEROS v6 · LOCAL HTML TOOL

MikroTik PPPoE Failover Builder & Checker

Build primary/backup WAN failover commands, copy verification commands, and paste RouterOS output for a guided configuration check. Works locally in your browser; it does not connect to your router.

Before you apply: RouterOS commands can disconnect you from the router. Export and binary-backup first, use WinBox Safe Mode, keep local/LAN access, and apply in stages. This tool assumes a simple two-WAN IPv4 setup without policy routing, VRFs, PCC/load-balancing, or custom routing marks. It cannot guarantee production correctness without inspecting the whole router configuration.

1. Router & WAN settings

Use the exact PPPoE interface names from /interface pppoe-client print detail. Names are case-sensitive.

2. Pre-check / inspection commands
Run these first and save the output before changing configuration.


/system resource print
/system package print
/interface pppoe-client print detail
/ip address print detail
/ip route print detail
/ip firewall nat print detail
/ip firewall filter print detail
/ip firewall mangle print detail
/routing rule print detail
/ip route rule print detail




On some RouterOS v6 releases, one of the routing-rule commands may be unavailable. If so, run the remaining commands. Do not paste passwords, private keys, or other secrets into shared messages.






3. Verification commands
Run after applying setup; these outputs are useful for checking route state and traffic.


/interface pppoe-client print detail
/ip route print detail where comment~"FO-"
/ip route print detail where dst-address=0.0.0.0/0
/ip firewall nat print detail
/ping 1.1.1.1 count=5
/ping 8.8.8.8 count=5
/tool traceroute 1.1.1.1
/tool traceroute 8.8.8.8

5. Apply, test & rollback


1
Save /export file=before-failover and /system backup save name=before-failover. Use WinBox Safe Mode (Ctrl+X in Terminal).


2
Run pre-check commands. Confirm both PPPoE interfaces are running and identify any mangle rules, routing marks, recursive routes, or scripts that could conflict.


3
Generate commands and inspect them. Apply only when you can recover locally. Avoid blindly importing the whole file on a router with an existing complex setup.


4
Check route output. Each probe route should resolve through its own PPPoE interface. A probe route that is active does not by itself prove the probe IP answers ping. The primary default should be active when its probe works; backup should take over when primary fails.


5
Test a real primary PPPoE disconnect, then test upstream failure only in a maintenance window. Verify Internet from a LAN client, not just from the router.


Rollback commands (only remove this tool's named rules)


/ip route remove [find where comment="FO-DEFAULT-PRIMARY"]
/ip route remove [find where comment="FO-DEFAULT-BACKUP"]
/ip route remove [find where comment="FO-PROBE-PRIMARY"]
/ip route remove [find where comment="FO-PROBE-BACKUP"]
/ip firewall nat remove [find where comment="FO-NAT-PRIMARY"]
/ip firewall nat remove [find where comment="FO-NAT-BACKUP"]

# Only if automatic default routes were disabled by this setup:
/interface pppoe-client set [find where name="PRIMARY_NAME"] add-default-route=yes default-route-distance=1
/interface pppoe-client set [find where name="BACKUP_NAME"] add-default-route=yes default-route-distance=2


Replace PRIMARY_NAME and BACKUP_NAME with your actual names. Restore the original distance values if they differed. Rollback removes only the named rules, not existing NAT rules. If the previous config was complex, restore from your saved export rather than assuming these defaults.
